PoE2 Route AutoSplitter v2.1.3 development - Validation Summary

Compact premade generator / trial opt-in
- Premade UI uses Mode, Setup, and Ordered/Dynamic selectors instead of the former 41-row list.
- Modes: Area Completion, Boss Completion, Area + Boss Completion, Level Race.
- Setup choices include Campaign 100%/Any%, Act 1-4 100%/Any%, Interlude 1-3, All Interludes, Combination 100%/Any%, and Pinnacle for Boss Completion.
- Combination routes use a seven-item Act/Interlude checklist and preserve campaign group order.
- Area + Boss premades are constrained to Dynamic/unordered until an interleaved ordered mixed baseline is validated.
- Generated premades use the shared mixed ASL and generated poe2_mixed_route.txt / Premade-Route.lss files.
- Base area generation strips legacy G2_13 and G3_10_Airlock trial entries; trial areas are re-added only through the premade opt-in controls.
- Campaign/Act boss generation strips Sekhemas/Chaos trial identities until opted in. Pinnacle preserves its established 10-target list, including Zarokh and Trialmaster.
- Sekhemas supports sequential Floor 1-4 selection; enabling Sekhemas defaults to Floor 1 only. Ordered routes provide an independent Run-after selector for every selected floor.
- Chaos supports sequential 4/7/10-round stages plus optional Trialmaster for boss routes. Ordered routes provide an independent Run-after selector for each selected stage. Area Completion uses unique areaocc objectives for repeated active-trial visits.
- Ordered Area first-stage defaults: The Halani Gates (Sekhemas Floor 1), Chimeral Wetlands (Chaos 4-round). Later trial stages default to End of route until scheduled.
- Ordered Boss first-stage defaults: Jamanra, the Risen King (Sekhemas Floor 1), Xyclucian, the Chimera (Chaos 4-round). Later trial stages default to End of route until scheduled.
- Dynamic routes append selected trial objectives to the unordered completion pool, so objective count changes without imposing an encounter order.
- Shared mixed ASL recognizes Sekhemas floor-area prefixes and the active Chaos area, and supports areaocc|AREA~N for repeated logical visits to the same game area.
- Boss catalog coverage check: 84 non-support OCR identities are present in the shared mixed ASL; the only catalog identity intentionally absent is support-only Plagueling.
- Campaign 100% area source resolves to 97 non-trial objectives before opt-in; Campaign Any% area source resolves to 78.
- Campaign 100% boss source resolves to 67 non-trial objectives before opt-in; Campaign Any% resolves to 40. Pinnacle preserves its established 10-target list, including Zarokh and Trialmaster.
- Requested ordered insertion defaults are present in Campaign 100% and Campaign Any% source routes.
- SetupUI nullable Font warning source now uses SystemFonts.MessageBoxFont ?? Control.DefaultFont.

Custom catalog / repeated and dynamic boss objectives
- Custom Areas/Bosses use a shared Act 1-4 / Interlude 1-3 / Pinnacle filter; trial bosses remain excluded from the standard boss catalog selector.
- SetupUI exposes user-facing area/boss names only; internal IDs are not displayed in Custom catalogs/preview, premade insertion dropdowns, start-zone choices, or Trials policy descriptions.
- Added areas/bosses are excluded from availability until their route/pool entries are removed. Areas and Bosses both provide Add All for the currently visible filtered catalog.
- Ordered Multi-boss mode exposes per-boss positive Occurrences values (default 1). SetupUI emits unique `bossocc|BOSS~N` objectives and labels repeated rows `Boss — Kill N`.
- Dynamic/unordered custom boss mode treats selected bosses as an eligible pool and generates `bossslot|1..N` objectives. `Boss encounters required` defaults from BossWatcher/BossLists/campaign-any-v0.5.txt; current resolved baseline is 40.
- Mixed ASL validates @bossPool IDs, positive @bossTarget, unique bossocc keys, and boss-slot count == target.
- bossocc matching is occurrence-key based, so five separate BossWatcher GONE events for the same identity can complete five ordered objectives.
- bossslot matching never permanently marks the boss identity complete; repeated GONE events from the same eligible identity consume successive dynamic encounter slots.
- Custom .lss generation recognizes Repeated Boss and Dynamic Boss rows.

Custom level progression
- Setup UI Custom route includes Add level progression with Max Level (2-100) and Split Interval (1-100).
- Milestone generation matches 03-LevelRace/tools/Gen-LevelRace.ps1: interval milestones below the target plus Max Level as the final milestone.
- All 9,900 Max Level / Split Interval combinations within the UI range were checked for strictly increasing, duplicate-free output ending at Max Level.
- Generated level milestones are added to the custom objective preview and remain movable among area/boss objectives.
- Generate validates that the expected milestone set is intact and that level objectives appear in strictly ascending order.
- 14-Custom/PoE2-Mixed.asl accepts level|N objectives, validates 2..100 and ascending configuration order, and detects Client.txt 'is now level N' records.
- Ordered custom routes continuously track the highest observed character level.
- If an ordered level objective was already reached before it becomes current, the ASL suppresses that objective and calls LiveSplit SkipSplit so it is skipped rather than completed.
- Unordered routes continue to accept level objectives when their matching level event is reached.
- Native LiveSplit SkipSplit does not skip the final segment; this edge is diagnosed and documented for ordered mixed routes.
- Custom .lss generation labels level objectives as Level.
- BossWatcher is only required when at least one boss objective is present; level-only custom routes do not require it.

Dedicated Trials runtime
- Trials tab Generate/Deploy is enabled.
- Trial types: Trial of the Sekhemas / Trial of Chaos.
- Trial length/category: Sekhemas 1-4 floors; Chaos 4/7/10 rounds; optional Trialmaster for 10-round Chaos.
- Start is fixed and automatic; Manual start is not offered in the dedicated Trials tab.
- Sekhemas start directive is `Sanctum_1_*`; the shared mixed ASL normalizes actual `Sanctum_1_...` IDs before start matching.
- Chaos start directive is `G3_10`.
- Full Trial is the only selectable timing scope. Active Challenges Only is visible, disabled, and labeled NON-FUNCTIONAL / Active development.
- Boss policy is default and requires BossWatcher. Exit policy is selectable as an Alternative Rule.
- Sekhemas Exit policy completes on `G2_13`; Chaos Exit policy completes on `G3_10_Airlock`.
- Split modes: Final boss only, Each boss kill, Trial completion / exit only.
- Exit-only + Exit policy produces a single area objective and therefore does not require BossWatcher.
- Four-floor Sekhemas Each-boss mode produces five boss objectives: Rattlecage, two Hadi/Rafiq dynamic slots, Ashar, Zarokh.
- Hadi/Rafiq dynamic slots share only the Hadi/Rafiq pool, allowing either kill order.
- Chaos Each-boss mode uses sequential `bossany` slots from the Uxmal/Chetza/Bahlak restricted pool.
- Chaos Final-boss-only without Trialmaster uses `bossnth|chaos_final_N`; 4/7/10-round categories target the 1st/2nd/3rd random Chaos boss respectively.
- Generated Trials files: `Trial-Run.lss`, `PoE2-Trial.asl`, `poe2_mixed_route.txt`, `TRIAL_RULES.txt`, plus optional watcher state/event files when required.
- Functional Trials selections no longer carry a development-status label. Active Challenges Only remains explicitly NON-FUNCTIONAL and in active development.

PoE2 Route AutoSplitter v2.1.1 development hotfix - Validation Summary

Campaign start policy
- Modes 01-09 and 12-14 contain the Riverbank start gate.
- Entering G1_1 / The Riverbank arms the start while LiveSplit is Not Running.
- The timer starts only when a newly read Client.txt line contains:
    Wounded Man: Reach... Clearfell... Find the Miller...
- The initial new-character wake-up/setup window, movement to the Wounded Man, and first NPC interaction are therefore outside the timed attempt.
- Modes 04, 05, 12, 13, and 14 retain normal area-entry start behavior for configured non-Riverbank start areas.
- Pinnacle modes 10-11 remain manual-start and contain no Riverbank/Wounded-Man start gate.
- Riverbank remains an exploration objective. Existing successor-entry completion behavior remains intact; arbitrary departures do not complete the Riverbank segment.
- The opening Riverbank loading-screen bookkeeping is cleared when the official Wounded Man start fires, so pre-start load time is not applied to the attempt.

Game Time architecture
- All 14 ASL engines include enabled-by-default load-removed Game Time support.
- Each ASL uses an independent Client.txt reader for Game Time so route/boss event readers are not consumed or disturbed.
- `Got Instance Details` begins the live isLoading pause.
- `[LOADING SCREEN] (Area) Duration = X seconds` is parsed as the authoritative completed loading-screen duration.
- Each completed load corrects the difference between the observed live pause and the duration reported by Path of Exile 2.
- Boss intros/outros, dialogue, and scripted story events remain timed.
- Missing/stale optional manual-pause heartbeat fails open: Game Time continues rather than becoming stuck paused.

Optional GameTimeWatcher v0.4.3
- GameTimeWatcher is not required for normal load-removed Game Time.
- It is opt-in and only supplies actual manual-pause state for runners who choose to exclude manual pauses.
- Detection remains limited to the actual pause menu and Microtransaction Shop.
- Pause-menu recognition priority is RESUME GAME -> GAME PAUSED -> EXIT PATH OF EXILE.
- Live-test thresholds are 0.58 / 0.40 / 0.50 respectively; MTX remains 0.70.
- Pause-template scale variants are precomputed once at startup.
- Pause matching is restricted to narrow centered vertical bands instead of a broad ultrawide search.
- State heartbeat writes run on an independent background thread at the configured 250 ms cadence and are also signaled immediately for provisional/confirmed transitions.
- Options and Challenges/Achievements intentionally remain timed because PoE2 resumes the simulation there.
- No Client.txt tailing, boss-bar detection, voice-line detection, cutscene detection, movement tracking, or gameplay-input inference remains in GameTimeWatcher.
- It uses external screen capture/template matching only and does not read or modify Path of Exile 2 process memory.
- State-file/log I/O failures are caught and diagnosed instead of terminating the helper.
- Process wrappers returned by repeated GetProcessesByName scans are disposed before each scan returns.
- Game-window/process discovery remains throttled to 250 ms.
- Developer/internal diagnostics include detector scores, working/private memory, handles, threads, managed memory, GC counts, and analyzeMs.

GameTimeWatcher v0.4.2 provisional timestamp protocol
- State file version=2 supports RUNNING, PAUSED, PENDING_PAUSE, and PENDING_RUN.
- Every state transition includes `stateSequence` and `originUtcTicks`.
- Default provisional timeout is 1200 ms.
- ESC/controller Start publishes a pending state from the independent 5 ms input thread while PoE2 is foreground.
- The ASLs poll the optional manual-pause state every 50 ms (bounded by each ASL refresh rate).
- PENDING_PAUSE immediately participates in isLoading; PENDING_RUN immediately releases the manual isLoading hold.
- Accepted provisional transitions compensate the input-edge-to-ASL-poll interval.
- Rejected provisional transitions refund/re-remove the temporary interval through the existing Game Time correction accumulator.
- Missing/stale watcher state still fails open.
- State is published before diagnostic state/menu PNG encoding.
