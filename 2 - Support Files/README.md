# Path of Exile 2 Route AutoSplitter for LiveSplit — v3.0.0 Release Candidate

## Run validation / SHA-256 audit logging

Every setup generated by SetupUI includes a timing-neutral run audit. On LiveSplit start, the ASL creates a unique Run ID and writes an append-only SHA-256-chained event log. Committed splits record the segment name plus committed Game Time and Real Time. When a run finishes, resets, or the ASL exits, it writes a readable summary and a `.sha256` manifest.

SetupUI writes all run-verification evidence under the top-level `3 - verification files` directory. This includes `poe2_setup_validation.sha256`, `RUN_VALIDATION_README.txt`, `Verify-RunValidation.ps1`, the append-only `poe2_run_<RunId>.log`, its readable summary, and the per-run `poe2_run_<RunId>.sha256` manifest. The setup manifest hashes stable generated ASL/config/rules/support files inside `LiveSplit Target`. `.lss` files and mutable watcher/state logs are excluded because LiveSplit/watchers legitimately modify them during normal use.

Run validation is an audit/integrity aid, not tamper-proof anti-cheat. A runner controls the local machine and could replace software and generate a new internally consistent set of files.

## Vaal Ruins / Temple of Atziri UI policy (development scaffold)

The **Vaal Ruins** tab remains UI-only while Temple runtime transitions are being field-tested. Vaal Ruins is modeled as untimed setup/staging and Atziri's Temple as active timed **Temple Dive** content. The UI accepts 1-10 planned dives (default 1) and exposes **Completion Criteria** of Dive Number, Royal Architect, or Atziri.

Death-condition choices mirror Maps: **No deaths** (default), **First death**, or **Track all deaths**. An optional **First death** deathless-run condition forces and locks the death policy to First death. A tracked character is planned to be required whenever death events are used. Generate / Deploy remains disabled on this tab until the Temple runtime state machine is implemented.

## Maps lifecycle policy v2 (development test)

SetupUI's **Maps** tab now builds Dynamic/unordered map runs around exact Client.txt `Map<name>` + seed identity rather than the earlier level-65+/hideout candidate heuristic. **The timer will automatically start when first entering the map. A valid run is from first entry to first exit after the area boss kill.**

Maps now has two **Game Time policies**. **PoE2 Map Completion** is the default: after a successful first exit following the area-boss kill, Game Time pauses between maps and resumes on the next new map entry. **Continuous Game Time** counts all non-loading time after the run starts; only loading-screen exclusion and the configured Manual Pause policy may pause Game Time.

BossWatcher ordinary-map qualification is identity-gated: a deterministic map boss must be recognized by database OCR before its disappearance can qualify the map. LiveSplit normally commits `SUCCESS` when Client.txt confirms the first real exit after qualification. A premature exit remains unresolved and same-seed re-entry continues the attempt. If a different map seed confirms `FAILED`, the default PoE2 Map Completion policy removes the intervening setup time, while Continuous Game Time preserves it. For a verified boss that was already missing before a very fast external exit, a guarded exit assist can confirm the boss after the exit and backdate the split boundary to that saved exit without forcing Continuous Game Time to rewind. Completed-map re-entry never creates another map completion.

Maps exposes four run endpoints: fixed map count, until first death, manual finish via LiveSplit Start/Split, and selected Pinnacle boss defeat. It also exposes three death policies: no tracking (default), end on first death, and tracked `Death [x]` rows. Character Name is required only when death tracking is active and is validated as Unicode letters plus `_`; runtime matching is an exact configured-name comparison against Client.txt death notifications.

The common SHA-256 run audit records committed dynamic map/death/Pinnacle rows plus Maps lifecycle events such as seed entry, boss qualification, premature exit, success/failure, rollback, and optional tracked-player death. See `4-README's_and_Diagnostics\Diagnostics\MAPS-POLICY-TEST-NOTES.md`.


### Client.txt localization hardening

Generated ASLs use canonical internal Area IDs and map seeds as runtime identity whenever those fields are available. Load/area parsing no longer depends solely on English phrases such as `Generating level`, `Got Instance Details`, or `[LOADING SCREEN]`; it also recognizes the observed message-site hash families and parses the language-independent structural fields around them. Exact message hashes have changed between PoE2 builds, so family matching is used instead of a single current hash. `You have entered ...` remains a legacy fallback only. Real non-English Client.txt samples are still needed to verify that these message-site families and structural field ordering remain consistent across every supported game locale.

This release uses a short archive root (`PoE2AS-v3.0.0`) and compact support names such as `01-Ordered`, `04-Checklist`, `BossWatcher`, and `GameTimeWatcher`. Generated .NET `bin` and `obj` folders are intentionally excluded from the release archive.

## LiveSplit setup

1. Launch `PoE2RouteSetup.exe`.
2. Select a premade configuration or build a custom route.
3. Optionally enable **Pause LiveSplit Game Time while PoE2 is manually paused**.
4. Press **Generate / Deploy Selected Setup**.
5. Open the generated `.lss` from `1 - User Setup\LiveSplit Target`.
6. Keep your own LiveSplit layout.
7. Add/edit the layout's **Scriptable Auto Splitter** component and point it at
   the generated `.asl`.
8. For Boss Rush or mixed routes, press **Start BossWatcher**.
9. If manual-pause removal was enabled, press **Start GameTimeWatcher**.

The Setup UI does not generate, copy, or modify `.lsl` files.


### PoE2 game language / watcher localization

SetupUI display language and PoE2 game language are separate settings. The PoE2 game language controls BossWatcher OCR and is written into each generated `poe2_run_settings.json`. BossWatcher v0.3.4 uses the corresponding OCR model plus verified localized boss names and converts a successful localized match back to the same invariant boss ID used by the route. GameTimeWatcher v0.4.5 reads the same game-language setting but relies primarily on pause-menu geometry and the paused banner rather than translated button text.

The first development localization catalog is deliberately incomplete; unsupported boss-name coverage fails conservatively instead of guessing.

## Game Time

Every deployed ASL has load removal enabled by default.

The ASL tails Path of Exile 2 `Client.txt` independently of its route/boss
reader. `Got Instance Details` begins the live Game Time pause for a zone
transition. When PoE2 later writes:

```text
[LOADING SCREEN] (Area Name) Duration = X seconds
```

the ASL uses that game-reported duration as the authoritative amount of load
time to remove and corrects any small log-observation difference.

Boss introductions, boss outros, NPC dialogue, and ordinary scripted story
sequences remain timed. Testing showed that PoE2 commonly allows useful
inventory management during those sequences, so they are treated as part of
the run rather than free time.

For load-removed timing, configure LiveSplit to display/compare against
**Game Time**.

### Optional manual-pause removal

GameTimeWatcher is **not required** for normal load removal.

It is only used when the runner enables the Setup UI option to pause LiveSplit
Game Time along with PoE2's real manual pause state. GameTimeWatcher v0.4.3 recognizes:

- the centered in-game pause menu; and
- the Microtransaction Shop when opened from that paused state.

For ESC/controller-Start transitions, v0.4.3 publishes a provisional timestamp immediately and lets the ASL hold/release Game Time on its next update while the screen detector verifies the result. Rejected candidates are compensated automatically, so the final Game Time remains screen-authoritative.

Options and Challenges/Achievements remain timed because PoE2 resumes the game
simulation while those interfaces are open.

The helper writes a heartbeat state file to `LiveSplit Target`. The ASL honors
a pause only while that heartbeat is fresh; a missing/stale helper fails open.

### GameTimeWatcher crash diagnostics

Enable **Developer console diagnostics** before pressing **Start
GameTimeWatcher** to launch the external watchdog instead of the helper directly.
It records watcher stdout/stderr, exit code, working/private/virtual memory,
handle/thread counts, CPU time/responsiveness, the internal watcher diagnostic
log, and matching Windows Application crash events under:

`4-README's_and_Diagnostics\Diagnostics` (PNG captures are stored in `Diagnostics\images`)

v0.3.1 also disposes the `Process` wrappers created by repeated PoE2 window
scans and throttles process discovery to 250 ms. The older loop enumerated
processes every ~10 ms without disposing those wrappers, making native handle
accumulation a plausible cause of the reported early exit. The watchdog remains
in place to confirm resource stability or capture a different failure.

## Setup UI

The Setup UI provides a compact premade generator plus the mixed custom-route builder. Premade generation is selected with **Mode**, **Setup**, and **Ordered / Dynamic** controls rather than a long preset table. Area and boss modes support Campaign 100% / Any%, Act, Interlude, All-Interlude, and Act/Interlude Combination scopes where applicable; Boss Completion also exposes Pinnacle. Optional Sekhemas/Chaos content can be scheduled per floor/stage with user-facing **Run after** placement controls on ordered routes. Level Race retains the 1–100 / every-10-level premade.

Sekhemas and Chaos are independent opt-ins on the Premade tab. The user chooses the trial depth/encounter count, and ordered routes choose the base area or boss immediately preceding the trial block. Dynamic routes add the selected trial objectives to the completion pool without imposing a trial order. The underlying static preset files remain in Support Files for reference/backward compatibility, but new premade deployments are generated as `Premade-Route.lss` + `PoE2-Premade.asl`.

Custom routes can combine supported areas, bosses, levels, and opt-in trial boss milestones. The catalog is filtered by Act / Interlude / Pinnacle and hides internal IDs; Areas and Bosses both provide **Add All** for the currently visible filtered list. Ordered routes support repeated copies of the same boss through unique occurrence objectives; dynamic/unordered routes use a user-selected eligible boss pool plus a configurable encounter target (defaulting to the current 40-boss campaign-required baseline). Deployment is staged before the active target is touched. Replacing a non-empty target requires confirmation.

## BossWatcher

BossWatcher handles identity-based Boss Rush / trial / Pinnacle events and the Maps structural boss-bar mode. Ordinary Maps context bypasses OCR and boss-name matching; selected Pinnacle objectives keep the identity/OCR path. Normal console output reports meaningful encounter/completion events, while `--dev-console` retains verbose diagnostics.

`.github\workflows\build-release.yml` runs for lowercase version tags such
as `v3.0.0` and can also be started manually. It builds the Setup UI,
BossWatcher, and optional GameTimeWatcher, assembles the four-directory runtime,
creates the portable ZIP and installer, and generates SHA-256 checksums.
