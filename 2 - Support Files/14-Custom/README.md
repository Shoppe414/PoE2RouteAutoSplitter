# Custom Route — Exploration + Boss Rush

Define a route containing any supported mixture of **area**, **boss**, and **level** objectives.

## Route file

Edit `poe2_mixed_route.txt` and copy it beside `LiveSplit.exe`.

```text
@start=G1_1
@order=unordered
area|G1_town
boss|the_bloated_miller
area|G1_2
boss|beira_of_the_rotten_pack
```

- `@start=<area id>` normally auto-starts when that area is detected. Special case: `@start=G1_1` arms the Riverbank start gate and timing begins on the Wounded Man final opening Client.txt line. Use `@start=manual` for manual start.
- `@order=unordered` accepts configured objectives in any order.
- `@order=ordered` accepts only the objective matching the current LiveSplit row.
- `area|<id>` uses the Exploration detector in `Client.txt`.
- `boss|<id>` uses BossWatcher's `poe2_boss_events.log`.
- `bossocc|<id>~N` is a uniquely keyed repeated occurrence of the same boss identity. It is intended for ordered repeated-boss challenges.
- `@bossPool=<id>;<id>;...` defines an eligible custom boss pool and `@bossTarget=N` defines the required encounter count. Pair those directives with `bossslot|1` through `bossslot|N`; every qualifying `GONE` event consumes one slot, including repeat kills of the same boss.
- `bossall`, `bossany`, and `bossnth` are specialized composite/dynamic objectives generated by SetupUI for trial policies.
- `level|N` uses the `Client.txt` `is now level N` event.
- `mapboss|N` is generated by the Maps tab. The ASL arms BossWatcher structural map mode for the current candidate map and consumes `MAP_GONE`; the row name is set from the generated map level rather than a boss identity.

After editing the route, create a matching `.lss` with:

```powershell
.\Gen-MixedLayout.ps1 -RouteFile .\poe2_mixed_route.txt -OutputLss '.\My-Mixed.lss'
```

The supplied example layout has four rows and matches the supplied example route. Load only one ASL component at a time. Boss objectives require `BossWatcher` to be running.

## Optional area completion mode

Custom routes continue to use entry-based area objectives by default. Advanced hand-edited routes may add `@areaCompletion=successor` when the `area|...` lines form a deliberate progression sequence. In that mode, an area is armed when entered and completes only when the next listed area is entered; unrelated detours and revisits do not trigger it. The Setup UI does not enable this automatically for custom routes.

## Game Time

Game Time removes Path of Exile 2 `Client.txt` loading-screen durations automatically. GameTimeWatcher is only required if the optional manual-pause removal setting is enabled during setup.


## Level objectives

Custom mixed routes also support `level|N` objectives (levels 2-100). Level-up detection uses the same `Client.txt` `is now level N` signal as the standalone Level Race mode. Level objectives must appear in strictly ascending numeric order in the route configuration, even when area/boss objectives are interleaved between them.

For **ordered** routes, the ASL continuously remembers the highest level observed. If a level milestone was reached while an earlier area/boss objective was still active, that level event cannot happen again. When the missed level later becomes the active LiveSplit row, the ASL uses LiveSplit's native **Skip Split** behavior and marks the level objective suppressed rather than completed. This lets the route continue automatically without falsely awarding the missed level split.

LiveSplit intentionally cannot Skip Split on the final segment. If an ordered mixed challenge can overlevel a milestone before it becomes active, keep a later objective after that level milestone.
